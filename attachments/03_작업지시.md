# 작업 지시서

**첫 메시지로는 아래 "0. 시작 지시"만 보내고, 단계는 하나씩 확인하며 진행한다.**

## 0. 시작 지시 (첫 메시지로 이것만 복사)

```
첨부한 파일은 이미 동작하는 웹 프로젝트다. 처음부터 다시 만들지 말고 이어서 작업한다.

먼저 01_현재구조.md 를 끝까지 읽어라. 구조, 실행 모델, 손대면 안 되는 것이 전부 거기 있다.
그다음 02_시장기획.md 를 읽어라. 앞으로 만들 기능의 설계다.

작업량이 많아서 여러 단계로 나눠 진행한다.
03_작업지시.md 에 단계가 정리되어 있다. 지금은 읽기만 하고, 내가 "1단계 시작"이라고 하면 그때 착수해라.

각 단계는 다음 규칙을 지킨다.
- 한 단계씩만 한다. 다음 단계를 미리 하지 마라.
- 끝나면 바꾼 파일과 이유를 한 줄로 요약하고, 내 확인을 기다려라.
- 매번 아래 세 가지를 점검하고 결과를 보고해라.
  1) 자바스크립트 문법 검사
  2) 클릭 처리 선택자에 빈 항목이 없는지
  3) 화면에서 쓰는 data-* 와 data-act 값이 전부 처리 코드에 등록돼 있는지
- 기존 기능이 깨지지 않았는지 확인해라. 특히 글 공개, 선택지 답글, 투표, 인물, 백업.

준비됐으면 읽었다는 것만 알려라.
```

---

## 진행 순서

**A. 시장** (1~7단계) → **B. 설정 분리** (8단계) → **C. 업적** (9단계)

시장을 먼저 하는 이유는 창고 화면에 들어갈 슬라이더가 시장에서 나오기 때문이고,
업적이 마지막인 이유는 상당수가 시장 집계에 걸려 있기 때문이다.

---

## A. 중고 시장

### 1단계 — 데이터 구조와 시장 탭 껍데기

- `DB.market`(물품 원본), `DB.owned`(보유), `DB.credit`(크레딧), `DB.listed`(현재 매물) 추가
- `normalize()`에 기본값 보정 추가
- 하단 탭에 "시장" 추가 (탭 6개가 된다)
- 시장 탭에 매물 목록 화면. 이 단계에서는 시세 없이 기준가만 표시
- 붙여넣기에서 `market` 키를 물품으로 분류
- 예시 물품 3~4개를 기본 데이터로 넣어 화면이 비지 않게 할 것

확인: 물품 붙여넣기가 되고, 시장 탭에 목록이 뜨는가.

### 2단계 — 시세 엔진

- 인물별 **가중 언급량** 계산 (최근 10개 ×1.0, 앞 20개 ×0.5, 앞 30개 ×0.2)
- `현재가 = 기준가 × 언급 배수`, 범위 10%~1000%
- 새 글이 공개될 때만 갱신
- 물품별로 최근 값 5~6개 보관, 비교 구간(기본 10분) 대비 변동률 표시
- 목록과 상세에 현재가와 변동률 표시

확인: 인물이 언급될수록 값이 오르는가. 언급이 끊기면 떨어지는가.

### 3단계 — 거래

- 물품 상세에 호가 입력창과 사기/팔기 버튼
- 시세 대비 유불리로 체결 시간 결정 (기획서 표 참조)
- 대기 주문은 실제 시각 기준. `DB.pending`과 같은 방식으로 처리
- 체결되면 크레딧 증감, 보유 목록 반영
- 동시 다건 가능, 취소 불가
- 크레딧 획득: 공감 5, 댓글 20, 투표 10. 바닥 보정 포함

확인: 사고팔기가 되는가. 유리하게 부르면 빨리 체결되는가.

### 4단계 — 순환

- 동시 노출 3~4개. 나머지는 대기
- 하한(기준가 10%)에 닿으면 매물 소멸, 1시간 뒤 같은 기준가로 재등장
- 보유 중인 물건은 순환에서 제외, 팔면 복귀
- 시장 탭에 "내 물건" 구역

확인: 매물이 사라졌다 다시 나오는가. 보유 물건이 시장에 중복으로 뜨지 않는가.

### 5단계 — 감상평

- 매물이 등장하는 순간의 시세로 up/mid/down 구간 결정, 그 판 동안 고정
- 결정된 구간의 감상평이 시간차를 두고 하나씩 붙음
- 답글 없음. 구간당 2~3개까지

확인: 값이 떨어진 뒤 재등장한 물건에 down 감상평이 붙는가.

### 6단계 — 물품 프롬프트

- `DEFAULT_MTPL` 추가, 기계실 생성기에 "물품" 모드 추가
- 자리표시자 `{인물}`(인물 목록), `{개수}`(슬라이더)
- 프롬프트 원문은 `04_물품프롬프트.md` 참조
- 기존 템플릿 편집과 같은 방식으로 수정·복원 가능하게

확인: 생성한 프롬프트를 AI에 넣어 나온 결과가 그대로 붙여넣어지는가.

### 7단계 — 시장 슬라이더

창고 화면에 추가. 기존 `SLD` / `slider()` 구조를 그대로 쓴다.

시세 변동 계수 · 상한 배수 · 하한 배수 · 동시 노출 수 · 재등장 시간 ·
체결 시간 배수 · 크레딧 보상량 · 감상평 구간 경계 · 변동률 비교 구간

확인: 슬라이더를 움직이면 시장 동작이 실제로 달라지는가.

---

## B. 설정 분리

### 8단계

- 헤더 `•••` → 기계실 / 창고 두 갈래를 고르는 화면
- **기계실**: 프롬프트 생성기(게시글·투표·물품), 생성 옵션 슬라이더, 템플릿 편집 4종
- **창고**: 글 불러오기, 현황과 출처, 공개 속도, 시간대 반영,
  시장 운영 슬라이더, 백업, 저장 공간, 초기화

시장 설정은 두 곳으로 나뉜다. 물품을 **만드는** 프롬프트는 기계실,
시장이 **굴러가는** 규칙은 창고다. 원칙은 "무엇을 만들 것인가 / 만들어진 것을 어떻게 풀 것인가"다.

확인: 기존 설정 항목이 하나도 빠지지 않았는가.

---

## C. 업적

### 9단계

착수 전에 업적 목록(이름·조건·티어)을 별도 문서로 전달한다. **목록 없이 시작하지 마라.**

- 보상 없음. 표시만 한다
- 나의 탭에 구역 추가
- 미달성은 `???`로 가리되 전체 개수는 공개 ("24개 중 5개 달성")
- 티어 브론즈~챌린저 8단계. 업적마다 고정
- 달성 시 팝업

필요한 집계는 1~7단계에서 이미 쌓여 있어야 한다. 거래 횟수, 최고 수익률,
인물별 관심도(구현 완료), 투표 참여 수 등.

---

## 매 단계 공통 규칙

1. 한 단계씩. 끝나면 확인을 기다린다.
2. 큰 블록을 치환한 뒤에는 반드시 문법 검사. 함수 헤더가 사라지는 사고가 실제로 있었다.
3. 클릭 선택자를 수정하면 빈 항목이 남지 않았는지 확인. 쉼표 하나로 모든 클릭이 먹통이 된 적 있다.
4. 사용자 입력은 DOM이 아니라 `S`에 보관한다. 3초마다 도는 자동 갱신에 값이 날아간다.
5. 스키마를 바꾸면 프롬프트 템플릿도 같이 고친다.
6. `01_현재구조.md`의 "손대면 안 되는 것" 8개를 매번 확인한다.
