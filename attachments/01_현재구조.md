# 캠퍼스타임 — 현재 구조 설명서

에브리타임 형태의 대학 커뮤니티 시뮬레이터다.
미리 만들어둔 글·댓글·투표를 시간에 맞춰 하나씩 공개해, 커뮤니티가 살아 돌아가는 것처럼 보이게 한다.
내용은 AI 채팅으로 생성해 앱에 붙여넣는다. 서버도 빌드 도구도 없고 `campustime.html` 한 파일로 끝난다.

---

## 1. 실행 모델

### 피드 시계
실제 시각이 아니라 `DB.clock`(누적 밀리초)이 기준이다.

```
tick()  // 3초마다
  DB.clock += (지금 − 마지막 tick)
  공개 시각이 지난 글을 순서대로 게시
  게시된 글마다 대기 중인 댓글을 하나씩 붙임
  변한 게 있으면 저장 후 재렌더
```

- 창을 닫아도 시간은 흐른다. 다시 열면 밀린 만큼 채워지되, **한 번에 최대 2개까지만** 따라잡는다.
- 화면의 "3시간 전"도 실제 시각이 아니라 이 시계 기준이다 (`ago()`).
- **시간대 반영**: 실제 시각에 따라 간격에 배수가 붙는다. 새벽 ×4.5, 밤 ×0.6 등. `TOD` 배열과 `rate()` 참조. 설정에서 끌 수 있다.

### 두 줄기의 독립 공개
일반 글(`DB.feed`)과 투표(`DB.polls`)는 **각자의 대기열과 공개 시각**을 가진다.

- `DB.revealed` / `DB.lastPostAt` — 일반 글
- `DB.prevealed` / `DB.plastAt` — 투표
- 투표는 반 칸 늦게 시작해 두 줄기가 같은 순간에 겹치지 않는다.
- 당겨서 새로고침하면 **지금 보고 있는 탭의 것만** 공개된다.

이 분리는 의도된 설계다. 하나로 합치지 마라.

### 선택지 답글
글에 달린 선택지를 누르면 내 댓글이 올라가고, 몇 초 뒤 예약된 답글이 내 댓글의 대댓글로 붙는다.

- 대기 중인 답글은 `DB.pending`에 쌓이고 `pulse()`가 1초마다 처리한다.
- 지연은 **실제 초**다. 피드 시계와 무관하다. 몇 초짜리 대화가 배속에 휘둘리면 어색해진다.
- 대댓글은 **한 단계까지만**이다. 대댓글에 달리는 답글은 `topOf()`가 원 댓글로 끌어올린다.

### cmap — 답글 대상 고정
원본 데이터의 `reply: 0`은 배열 순번이라, 내 댓글이 중간에 끼면 대상이 밀린다.
글마다 `cmap`(원본 순번 → 실제 댓글 id)을 두고 **id로 연결**해 이 문제를 막았다.
`publishComment`, `chooseReply`, `sendComment` 모두 이 경로를 쓴다.

## 2. 데이터

### 상태
- `DB` — 저장됨: `feed`, `polls`, `posts`, `people`, `pending`, `sources`, `cfg`, `clock`, `lastTick`,
  `revealed`, `prevealed`, `lastPostAt`, `plastAt`, `nextId`, `tpl`, `ptpl`, `qtpl`
- `S` — 저장 안 됨: 화면 상태(`tab`, `view`, `post`, `sheet`, `q`, `ment`, `flash`, `g` 등)

### 저장
`store` 계층만 거친다. **IndexedDB가 주 저장소**이고, 쓸 수 없는 환경에서만 localStorage로 자동 폴백된다.
`save()`는 0.5초 묶어 처리하고, 화면을 벗어날 때 `flush()`로 즉시 기록한다.
localStorage를 직접 부르지 마라.

### ID 규칙
모든 id는 `uid()` (= `DB.nextId++`) 하나로 발급한다. 글·댓글·인물 구분 없이 전역 유일하다.

### 원본 참조
공개된 글은 `fi`(원본 인덱스)와 `pk`(`'feed'` 또는 `'poll'`)를 들고 있다.
원본은 `srcOf(p)`로 꺼낸다. 배열을 직접 인덱싱하지 마라.

## 3. 입력 데이터 스키마

### 게시글
```json
{
  "title": "글 제목",
  "body": "본문. \n 으로 줄바꿈",
  "likes": 42,
  "scraps": 5,
  "image": "빈 자리에 놓인 텀블러 사진",
  "arc": "도서관 자리 사건",
  "comments": [
    { "text": "댓글", "likes": 3 },
    { "text": "0번 댓글에 다는 글쓴이 답글", "writer": true, "reply": 0 }
  ],
  "choices": [
    { "text": "눌러서 달 댓글", "to": 0,
      "replies": [ { "text": "몇 초 뒤 도착", "likes": 2 } ] }
  ]
}
```

- `image` — **실제 사진이 아니라 설명 문구 한 줄**이다. 점선 상자에 "📷 …"로 뜬다.
  파일이나 base64로 바꾸지 마라.
- `arc` — 같은 사건을 다루는 글에 붙이는 이름표. 앱이 이 값으로 글을 묶어 "이어지는 이야기"를 보여준다.
- 시간 관련 항목(`after` 등)은 무시하고 지운다. 공개 속도는 앱이 정한다.

### 투표
게시글과 같은 배열에 섞여 와도 된다. `options`가 있으면 앱이 투표로 자동 분류한다.
```json
{ "title": "조별과제 vs 개인과제", "body": "조건 한 줄",
  "options": ["조별과제만", "개인과제만"], "votes": [63, 412],
  "comments": [...], "choices": [...] }
```

### 인물
```json
{ "people": [
  { "name": "김대현 교수", "role": "전공 교수", "age": "40대 후반",
    "build": "180cm / 68kg", "shape": "마르고 어깨가 좁다",
    "memo": "여러 줄 가능. 외모·성격·습관을 여기에 적는다.",
    "photo": "data:image/jpeg;base64,..." } ] }
```

### 붙여넣기 형태
`[...]` 배열이거나 `{ "people": [], "posts": [] }` 객체 모두 받는다.
코드펜스나 앞뒤 잡소리가 섞여 있어도 배열/객체만 뽑아낸다 (`extract()`).
**업로드는 항상 누적**이다. 기존 데이터를 덮어쓰지 않는다.

## 4. 화면

하단 탭 5개.

| 탭 | 내용 |
|---|---|
| 게시판 | 공개된 일반 글. 상단에 실시간 인기 검색어, 하단에 새로고침 |
| 투표 | 공개된 투표. 선택 전에는 버튼, 선택 후 막대와 퍼센트 |
| 인기 | `공감 + 댓글×3 + 스크랩×2` 순 상위 20 |
| 나의 | 내 댓글, 스크랩, 공감한 글 |
| 인물 | 언급 횟수 그래프, 인물 카드(프로필·관심도·언급된 글 보기) |

그 밖에 상세, 검색 결과, 언급된 글 목록, 설정 화면이 있다.
설정은 헤더의 흐릿한 `•••`로 들어간다. 몰입을 위해 일부러 눈에 안 띄게 뒀다.

### 렌더 방식
전체 다시 그리기다. `render()`가 `S.view`에 맞는 `v*()` 함수를 골라 `#app.innerHTML`에 넣는다.
이벤트는 `document`에 위임되고 `data-*` 속성으로 분기한다.

**입력 중에는 다시 그리지 않는다.** `busy()`가 참이면 `S.dirty`만 세우고 미룬다.
설정 화면, 열린 시트, 포커스된 입력 요소가 대상이다.
한글 조합 중에 DOM이 바뀌면 입력이 날아가기 때문이다.

## 5. 인물과 언급

- `buildMentions()` — 인물별 언급 횟수, 언급된 글 목록, 관심도를 한 번에 계산하고 캐시한다.
  전체 이름이 잡히면 줄임말은 중복으로 세지 않는다.
- **관심도** — 그 인물이 언급된 글에서 내가 한 행동의 무게 합.
  공감 1 · 스크랩 2 · 투표 참여 1 · 내 댓글 3.
- 캐시 키에 상호작용 무게가 들어 있어, 공감만 눌러도 갱신된다.

## 6. 손대면 안 되는 것

1. 단일 HTML 구조. 외부 CDN, 번들러, npm 프로젝트로 바꾸지 마라. `file://`에서 바로 도는 게 전제다.
2. `store` 계층. localStorage 직접 호출 금지.
3. 시각 표시를 `Date.now()`로 되돌리지 마라. 피드 시계와 어긋난다.
4. 선택지 답글 지연을 피드 시계로 옮기지 마라. 실제 초여야 한다.
5. 게시판은 하나다. 카테고리를 다시 만들지 마라.
6. 사진은 설명 문구다. 실제 이미지 파일이나 base64로 바꾸지 마라.
7. 일반 글과 투표의 공개 일정 분리를 합치지 마라.
8. 스키마를 바꾸면 프롬프트 템플릿(`DEFAULT_TPL`, `DEFAULT_PTPL`, `DEFAULT_QTPL`)도 같이 고쳐라.

## 7. 실제로 겪은 사고

작업할 때 같은 실수를 반복하지 않도록 적어둔다.

**클릭 선택자에 빈 항목** — 기능을 제거하며 `[data-chat],` 를 지웠는데 쉼표가 남아
`closest('...,[data-person],')`가 되었다. 선택자 전체가 무효가 되어 **모든 클릭이 먹통**이 됐다.
문법 검사로는 안 잡힌다. 아래 점검을 코드 수정 때마다 돌려라.

- 모든 선택자 문자열에 빈 항목이 없는지
- 화면에서 쓰는 `data-*`가 전부 처리 대상에 등록돼 있는지
- `data-act` 값 중 처리 코드(`case`)가 없는 것이 있는지

**함수 헤더 소실** — 큰 블록을 치환하다 `function chooseReply(...) {` 줄이 통째로 사라져
파일 전체가 깨졌다. 큰 치환 뒤에는 반드시 문법 검사를 하라.

**입력값 초기화** — 생성기 입력이 DOM에만 있어서, 3초마다 도는 자동 갱신에 값이 날아갔다.
사용자 입력은 반드시 `S`에 보관하고 렌더 시 거기서 읽어라.
